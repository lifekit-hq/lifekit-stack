# intake-to-vault

The software half of "take the knowledge from a judged video as reference": an hourly systemd
timer (installed by `install-intake-to-vault.sh`, runbook "Intake to vault") that files each
accepted [video-eval](../../skills/video-eval/SKILL.md) report into the memory vault, with no
model turn. Per report whose `Verdict:` is `accept`, `intake_to_vault.py` writes, through the
vault's own `bin/` gates:

| What | Where | Gate |
| --- | --- | --- |
| One immutable source page: clipper frontmatter, then the report and the transcript it was judged on, both verbatim in fenced blocks | `sources/<judged date>-video-<key>-<rubric>.md` | `bin/lint.sh --changed` must have no high or medium finding on it, else the page is removed and the run fails |
| Its index line | `index.md` | regenerated by `bin/index.sh` |
| One dated line linking the page | the owning project's `log.md`, else the root `log.md` as kind `intake` | `bin/log.sh` (one line, 400-byte cap, commits its own line) |

Inputs are read-only: `reports/` and `transcripts/` in the gateway's intake directory
(`/var/lib/lifekit/intake`). memory-sync commits the page and the index like any vault edit.

Behaviour worth knowing:

- **Accept only.** A `park` or a `drop` is not filed: the vault keeps only what the owner
  accepts (vault `CORE.md`, structured intake), and the private intake index already records
  every item judged and why. `ROUTED_VERDICTS` is the one switch.
- **Owning project, no guessing.** The report's `Project:` line names the project when its whole
  value, or its start followed by a character no project name has (`lifekit-stack (deploy
  scripts)`), is a vault project with a `log.md`; the longest name wins. Anything else goes to
  the cross-project `log.md`, which names the judge's `Project:` text.
- **Idempotent and crash-safe.** Each step is checked first: the page exists and names the same
  source URL, the index lists it, a living or archived log links it. A run that stopped half-way
  is completed by the next one; nothing is written twice and a page is never rewritten. Two keys
  that share a slug get a hash-suffixed name.
- **Transcript retention.** Transcripts live 14 days; a report filed after that gets a page that
  says the transcript was not kept.
- **Vault etiquette.** It skips while `/srv/memory/.model-pass` is under an hour old (the rule
  `memory-sync.sh` follows), runs as `lifekit` (the vault's owner and the only account that
  reads the 0700 intake directory), and commits as memory-sync does.

Tests: `scripts/tests/test_intake_to_vault.py`.
